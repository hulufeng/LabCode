## 一、项目概述

### 1.1 项目目标

LabCode 是一款集成 Monaco 编辑器 + AI 智能体 + 内置终端 + 测试运行器的桌面开发工具，核心亮点是 AI 能真正动手读写代码、执行命令、运行测试。

### 1.2 技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| **桌面框架** | Electron v28 | 跨平台桌面应用 |
| **编辑器** | Monaco Editor v0.45 | VS Code 同款编辑器 |
| **终端** | xterm.js + node-pty | 真实终端 |
| **前端** | HTML5 + CSS3 + JS (ES6+) | 原生 JS，无框架 |
| **后端** | Node.js | Electron 主进程 |
| **图标** | Tabler Icons (MIT) | 可商用图标 |
| **AI** | DeepSeek / 通义千问 / MiniMax | 多模型支持 |

### 1.3 项目结构

```
LabCode/
├── desktop-app/           # 桌面客户端（核心）
│   ├── main/              # Electron 主进程
│   │   ├── index.js       # 主进程入口
│   │   ├── preload.js     # 预加载脚本
│   │   └── terminal.js    # 终端服务
│   ├── renderer/          # 渲染进程
```

## 四、代码规范

### 4.1 JavaScript 规范

```javascript
// ✅ 好的写法
function calculateSum(numbers) {
  return numbers.reduce((sum, num) => sum + num, 0);
}

// ❌ 不好的写法
function sum(n){
  let s=0;
  for(let i=0;i<n.length;i++){s+=n[i]}
  return s;
}
```

**规则：**
- 使用 ES6+ 语法（箭头函数、解构、模板字符串等）
- 缩进使用 2 个空格
- 字符串使用单引号
- 函数命名使用驼峰命名法（`calculateSum`）
- 类命名使用帕斯卡命名法（`TerminalManager`）
- 常量使用大写蛇形命名法（`MAX_RETRY_COUNT`）
- 注释使用中文
- 每个函数不超过 50 行
- 每个文件不超过 500 行（超过则拆分）

### 4.2 CSS 规范

```css
/* ✅ 好的写法 */
.dropdown-menu {
  position: absolute;
  top: 100%;
  left: 0;
  min-width: 240px;
  background: var(--bg-secondary);
  border: 1px solid var(--border-color);
  border-radius: var(--radius-md);
  box-shadow: 0 8px 24px rgba(0, 0, 0, 0.15);
  padding: 6px 0;
  z-index: 10000;
}

/* 类名使用 kebab-case */
.dropdown-item:hover {
  background: var(--bg-hover);
}
```

**规则：**
- 类名使用 kebab-case（`dropdown-menu`、`dropdown-item`）
- 使用 CSS 变量定义主题色
- 属性按字母顺序排列
- 缩进使用 2 个空格
- 避免使用 `!important`
- 避免内联样式

### 4.3 HTML 规范

```html
<!-- ✅ 好的写法 -->
<div class="dropdown-menu" id="dropdown-file">
  <div class="dropdown-item" data-action="new-project">
    <span class="dropdown-label">新建项目</span>
    <span class="dropdown-shortcut">Ctrl+N</span>
  </div>
</div>
```

**规则：**
- 使用语义化标签
- 属性值使用双引号
- 缩进使用 2 个空格
- id 使用 kebab-case
- data-* 属性用于 JS 交互

### 4.4 提交信息规范

```
<类型>(<范围>): <简短描述>

[详细描述（可选）]

[关联 Issue（可选）]
```

**类型：**
- `feat` - 新功能
- `fix` - Bug 修复
- `docs` - 文档更新
- `style` - 代码格式（不影响功能）
- `refactor` - 重构
- `test` - 测试相关
- `chore` - 构建/工具相关

**示例：**
```
feat(terminal): 集成 xterm.js 实现真实终端

- 添加 TerminalManager 类
- 实现终端创建、写入、调整大小
- 添加降级模式支持

Closes #123
```

## 五、版本管理（Git）

### 5.1 分支策略

```
main (生产环境)
  ↑
release/* (发布分支)
  ↑
develop (开发分支)
  ↑
feature/* (功能分支)
bugfix/* (Bug修复分支)
hotfix/* (紧急修复分支)
```

### 5.2 分支命名

| 分支类型 | 命名格式 | 示例 |
|----------|----------|------|
| 功能分支 | `feature/<功能名>` | `feature/ai-thinking` |
| Bug 修复 | `bugfix/<Bug描述>` | `bugfix/terminal-crash` |
| 紧急修复 | `hotfix/<问题描述>` | `hotfix/login-error` |
| 发布分支 | `release/<版本号>` | `release/v1.0.0` |

### 5.3 工作流程

```bash
# 1. 从 develop 创建功能分支
git checkout develop
git pull origin develop
git checkout -b feature/ai-thinking

# 2. 开发并提交
git add .
git commit -m "feat(ai): 添加思考过程展示"

# 3. 推送到远程
git push origin feature/ai-thinking

# 4. 创建 Pull Request 到 develop
# 在 GitHub/GitLab 上创建 PR，等待代码审查

# 5. 代码审查通过后合并
# 在 PR 页面点击 Merge

# 6. 删除功能分支
git branch -d feature/ai-thinking
git push origin --delete feature/ai-thinking
```

### 5.4 代码审查清单

- [ ] 代码符合规范
- [ ] 没有硬编码的密钥/密码
- [ ] 错误处理完善
- [ ] 注释清晰
- [ ] 没有重复代码
- [ ] 性能考虑
- [ ] 安全考虑
- [ ] 测试覆盖
- [ ] 文档更新

## 九、测试和发布流程

### 9.1 测试流程

```
开发完成 → 单元测试 → 集成测试 → 功能测试 → 性能测试 → 安全测试 → 发布
```

### 9.2 测试类型

| 测试类型 | 工具 | 说明 |
|----------|------|------|
| **单元测试** | Jest / Mocha | 函数、类的单元测试 |
| **集成测试** | Playwright / Spectron | Electron 应用集成测试 |
| **功能测试** | 手动 + 自动化 | 功能点验证 |
| **性能测试** | Lighthouse / 自定义 | 启动时间、内存占用、响应速度 |
| **安全测试** | npm audit / 自定义 | 依赖漏洞、XSS、注入 |

### 9.3 发布流程

```
develop → release/v1.0.0 → 测试 → Bug 修复 → main → 打 Tag → 发布
```

**版本号规则：** `主版本.次版本.修订号`（Semantic Versioning）
- 主版本：不兼容的 API 变更
- 次版本：向下兼容的功能性新增
- 修订号：向下兼容的问题修正

**示例：**
- `v1.0.0` - 首个正式版本
- `v1.0.1` - Bug 修复
- `v1.1.0` - 新增功能
- `v2.0.0` - 重大变更
