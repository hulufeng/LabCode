## 一、项目概述

LabCode 是一款集成 Monaco 编辑器 + AI 智能体 + 内置终端 + 测试运行器的桌面开发工具，核心亮点是 AI 能真正动手读写代码、执行命令、运行测试，通过三种权限模式保障安全，支持通用软件开发和嵌入式开发（Arduino/ESP-IDF/STM32）。

本项目基于 TrieCode 实际操作记录进行仿写，实现了 TrieCode 的核心 AI 智能体功能。

## 五、核心功能实现说明

### 5.1 AI 思考过程展示

#### 功能说明

在 AI 回复之前，先展示 AI 的思考过程，包括需求识别、方案设计、工具选择、执行计划等。思考过程默认折叠，用户可以点击展开查看详细推理。

#### 实现位置

- **HTML**：`renderer/index.html` — 无固定结构，通过 JS 动态生成
- **CSS**：`renderer/css/style.css` — `.thinking-block`、`.thinking-header`、`.thinking-content`
- **JS**：`renderer/js/app.js`
  - `addThinkingBlock(content, duration)` — 创建思考过程块
  - `AgentRunner._generateThinking(userInput, result)` — 生成思考过程内容
  - `AgentRunner.run()` — 在调用 AI 后触发思考过程展示

#### 实现原理

1. AgentRunner 在调用 AI 生成响应后，根据用户输入和 AI 响应生成思考过程
2. 思考过程包括：需求识别、方案设计、工具选择、执行计划、即将调用工具、预期结果
3. 通过 `addThinkingBlock()` 函数在 AI 对话区域创建可折叠的思考过程块
4. 用户点击思考过程头部可以展开/折叠详细内容

#### 代码示例

```javascript
// 创建思考过程块
function addThinkingBlock(content, duration) {
  const area = document.getElementById('ai-chat-area');
  const id = 'thinking-' + (++thinkingBlockId);
  const block = document.createElement('div');
  block.className = 'chat-message ai';
  block.innerHTML = `
    <div class="chat-avatar">🧠</div>
    <div class="chat-bubble">
      <div class="thinking-block" id="${id}">
        <div class="thinking-header" onclick="...">
          <span>思考过程</span>
          <span>${duration}s</span>
        </div>
        <div class="thinking-content">${content}</div>
      </div>
    </div>`;
  area.appendChild(block);
}
```

### 5.2 工具调用记录

#### 功能说明

改进版工具调用展示，显示工具名、参数、结果，支持展开/折叠。状态图标包括：执行中（⏳）、完成（✓）、失败（✕）、等待确认（⏸）。

#### 实现位置

- **CSS**：`renderer/css/style.css` — `.tool-call-block`、`.tool-call-header`、`.tool-call-detail`
- **JS**：`renderer/js/app.js`
  - `addToolCallBlock(tool, status, summary, args, result)` — 创建工具调用块
  - `updateToolCallBlock(id, status, summary, result)` — 更新工具调用块状态
  - `AgentRunner._toolStep(id, tool, status, summary)` — 工具调用状态回调

#### 实现原理

1. AgentRunner 在执行工具调用时，通过 `onToolStep` 回调通知渲染进程
2. 渲染进程通过 `addToolCallBlock()` 创建工具调用块，显示工具名和状态
3. 工具执行完成后，通过 `updateToolCallBlock()` 更新状态和结果
4. 用户点击工具调用头部可以展开/折叠查看参数和结果详情

#### 代码示例

```javascript
// 创建工具调用块
function addToolCallBlock(tool, status, summary, args, result) {
  const id = 'toolcall-' + (++toolCallBlockId);
  const block = document.createElement('div');
  block.innerHTML = `
    <div class="tool-call-block" id="${id}">
      <div class="tool-call-header">
        <span class="tool-call-status ${status}">⏳</span>
        <span class="tool-call-name">${tool}</span>
        <span class="tool-call-summary">${summary}</span>
      </div>
      <div class="tool-call-detail">
        <div class="tool-call-args">参数: ${JSON.stringify(args)}</div>
        <div class="tool-call-result">结果: ${result}</div>
      </div>
    </div>`;
  return id;
}
```

### 5.3 计划进度面板

#### 功能说明

独立的计划进度面板，显示多步骤任务的进度。包括进度条、步骤列表、完成/执行中/待执行状态标记。

#### 实现位置

- **HTML**：`renderer/index.html` — `#plan-progress-panel`、`#plan-progress-count`、`#plan-progress-bar-fill`、`#plan-progress-steps`
- **CSS**：`renderer/css/style.css` — `.plan-progress-panel`、`.plan-progress-bar`、`.plan-progress-step`
- **JS**：`renderer/js/app.js`
  - `planProgressManager` — 计划进度管理类
  - `planProgressManager.setSteps(steps)` — 设置步骤
  - `planProgressManager.startStep(index)` — 开始执行步骤
  - `planProgressManager.completeStep(index, success)` — 完成步骤
  - `planProgressManager.render()` — 渲染面板

#### 实现原理

1. AgentRunner 在制定计划后，通过 `onPlanProgress` 回调通知渲染进程
2. 渲染进程通过 `planProgressManager.setSteps()` 设置步骤列表
3. 每执行一个步骤，通过 `startStep()` 更新当前执行步骤
4. 步骤完成后，通过 `completeStep()` 更新完成状态
5. 面板自动计算进度百分比并更新进度条

#### 代码示例

```javascript
const planProgressManager = {
  steps: [],
  currentStep: -1,
  
  setSteps(steps) {
    this.steps = steps.map(s => ({ ...s, status: 'pending' }));
    this.render();
    this.show();
  },
  
  startStep(index) {
    this.currentStep = index;
    this.steps[index].status = 'running';
    this.render();
  },
  
  completeStep(index, success = true) {
    this.steps[index].status = success ? 'done' : 'error';
    this.render();
  },
  
  render() {
    const doneCount = this.steps.filter(s => s.status === 'done').length;
    const progress = (doneCount / this.steps.length) * 100;
    document.getElementById('plan-progress-bar-fill').style.width = progress + '%';
    // ... 渲染步骤列表
  }
};
```

### 5.4 权限确认弹窗

#### 功能说明

详细的权限确认弹窗，当 AI 执行高风险操作时弹出，提供4种选项：
- **允许一次** — 仅允许本次操作
- **本会话允许** — 本次会话中允许此类操作
- **按此修改** — 修改权限规则，以后自动允许
- **拒绝** — 拒绝本次操作

#### 实现位置

- **HTML**：`renderer/index.html` — `#permission-modal`、`#permission-command`、`#permission-detail`
- **CSS**：`renderer/css/style.css` — `.permission-modal`、`.permission-warning`、`.permission-command`
- **JS**：`renderer/js/app.js`
  - `showPermissionModal(tool, command, detail, callback)` — 显示权限弹窗
  - `hidePermissionModal()` — 隐藏权限弹窗
  - `handlePermissionChoice(choice)` — 处理用户选择
  - `AgentRunner.run()` — 在需要权限确认时调用 `onPermissionRequest` 回调

#### 实现原理

1. AgentRunner 在执行工具调用前，通过权限判定逻辑判断是否需要用户确认
2. 如果需要确认，通过 `onPermissionRequest` 回调通知渲染进程
3. 渲染进程通过 `showPermissionModal()` 显示权限确认弹窗
4. 用户选择后，通过 `callback` 通知 AgentRunner
5. AgentRunner 根据用户选择决定是否执行工具

#### 代码示例

```javascript
function showPermissionModal(tool, command, detail, callback) {
  document.getElementById('permission-command').textContent = command;
  document.getElementById('permission-detail').textContent = detail;
  permissionCallback = callback;
  document.getElementById('permission-modal').style.display = 'flex';
}

// AgentRunner 中的权限确认处理
if (needsConfirm) {
  const userChoice = await new Promise((resolve) => {
    this.onPermissionRequest({
      tool: tc.name,
      command: command,
      detail: detail,
      callback: (choice) => resolve(choice)
    });
  });
  
  if (userChoice === 'reject') {
    // 拒绝执行
    continue;
  }
  // 允许执行
}
```

### 5.5 真实终端集成

#### 功能说明

基于 node-pty + xterm.js 的真实终端，支持 Windows PowerShell / cmd / bash。终端集成在底部面板中，支持新建终端、清屏、自动创建第一个终端。

#### 实现位置

- **主进程**：
  - `main/terminal.js` — `TerminalService` 类，node-pty 集成
  - `main/index.js` — 终端 IPC 通道处理
  - `main/preload.js` — 暴露 `window.LabCode.terminal` API
- **渲染进程**：
  - `renderer/js/terminal.js` — `TerminalManager` 类，xterm.js 集成
  - `renderer/js/app.js` — `setupTerminal()` 函数，终端界面集成
  - `renderer/index.html` — 终端容器 `#terminal-container`

#### 实现原理

1. **主进程**：
   - `TerminalService` 类封装 node-pty，提供创建终端、写入数据、调整大小、杀死终端等方法
   - 如果 node-pty 加载失败，自动降级到 child_process 模式
   - 通过 IPC 通道暴露终端操作给渲染进程
   - 终端数据输出通过 `webContents.send()` 实时推送到渲染进程

2. **渲染进程**：
   - `TerminalManager` 类封装 xterm.js，提供创建终端、附加到容器、写入数据等方法
   - 如果 xterm.js 加载失败，自动降级到简单的文本终端模式
   - 通过 `window.LabCode.terminal` API 与主进程通信
   - 监听主进程推送的终端数据输出，实时写入 xterm.js

3. **界面集成**：
   - 终端集成在底部面板的"终端"标签中
   - 包含工具栏（新建终端、清屏、状态显示）和终端内容区域
   - 应用启动时自动创建第一个终端

#### IPC 通道列表

| 通道 | 方向 | 说明 |
|------|------|------|
| `terminal:create` | 渲染→主 | 创建终端 |
| `terminal:write` | 渲染→主 | 向终端写入数据 |
| `terminal:resize` | 渲染→主 | 调整终端大小 |
| `terminal:getBuffer` | 渲染→主 | 获取终端缓冲区 |
| `terminal:clearBuffer` | 渲染→主 | 清除终端缓冲区 |
| `terminal:kill` | 渲染→主 | 杀死终端 |
| `terminal:list` | 渲染→主 | 获取终端列表 |
| `terminal:execute` | 渲染→主 | 执行命令（一次性） |
| `terminal:data:{id}` | 主→渲染 | 终端数据输出 |
| `terminal:exit:{id}` | 主→渲染 | 终端退出通知 |

#### 代码示例

```javascript
// 主进程：创建终端
ipcMain.handle('terminal:create', (_, options = {}) => {
  const terminal = terminalService.createTerminal(options);
  
  // 监听终端数据输出
  terminalService.onData(terminal.id, (data) => {
    mainWindow.webContents.send(`terminal:data:${terminal.id}`, data);
  });
  
  return { success: true, terminal };
});

// 渲染进程：创建终端并附加到容器
const result = await window.LabCode.terminal.create({ cwd: '/path/to/project' });
terminalManager.attachTerminal(result.terminal.id, container);

// 监听终端数据输出
window.LabCode.terminal.onData(result.terminal.id, (data) => {
  xterm.write(data);
});
```

在 `app.js` 的 `TOOL_DEFS` 数组中添加新工具定义：

```javascript
{
  name: 'my_tool',
  category: 'query',  // query(只读) / modify(修改) / execute(执行)

    type: 'object',

      param1: { type: 'string', description: '参数1' }
```
