# Monaco 编辑器空白问题 —— 根因定位与修复记录

日期：2026-09-10
项目：LabCode 桌面端（对标 TrieCode 1:1）
涉及版本：LabCode Setup 1.0.0.exe（本地 Monaco 打包版）

---

## 一、现象

- AI 对话正常回复，AI 用 write_file 创建文件后**中间标签页正常出现（如 main.c）**，但**编辑器区域始终空白**。
- 经 CDP 检查：`monaco.editor.getModels().length === 0`、`state.editor` 为 null、`window.monaco` 长时间 undefined。
- 手动在 DevTools 执行 `require(["vs/editor/editor.main"])` 后 20-25 秒内 `window.monaco` 变为可用，手动 `monaco.editor.create` 立即成功（modelCount=1）——证明**本地 Monaco 模块本身可加载、可创建**。

## 二、排查过程

| 步骤 | 假设 | 结果 |
|---|---|---|
| 1 | CDN Monaco 被 file:// + webSecurity 拦截 | 确认：命令行可访问 CDN，但渲染进程加载失败 → 已改为本地 `renderer/vs/` |
| 2 | 本地 vs 目录文件缺失 | 排除：手动 require 成功，113 个文件完整 |
| 3 | setupMonaco 的 AMD 回调未执行 | 疑似：手动执行相同逻辑成功，自动执行 105 秒无结果 |
| 4 | **init() phase 1 提前抛错 return** | **确认（根因）** |

### 决定性证据

用 CDP 开启 Runtime/Log 并 `Page.reload` 捕获到控制台错误：

```
[console:error] Init phase 1 error:
```

页面上实际存在错误横幅：

```
INIT ERROR: Cannot read properties of null (reading 'addEventListener')
```

逐段重放 phase 1 定位到具体函数：

```
bindEvents → app.js:4464:42 → document.getElementById('new-file-btn').addEventListener(...)
```

### 根因链条

1. 浅色主题 1:1 对齐改造时，HTML 中的"新建文件"按钮 id 从 `new-file-btn` 改成了 `quick-new-file`。
2. `bindEvents()` 第 4464 行仍按旧 id 取元素 → 取到 null → `null.addEventListener` 抛 TypeError。
3. `init()` 的 phase 1 catch 块捕获错误后执行 `return`，**直接跳过了后面的 `setupMonaco()` 和 `setupTerminal()`**。
4. 于是 Monaco 从未初始化 → AI 写的文件只有 tab、没有编辑器内容（终端同样受影响）。

## 三、修复内容（renderer/js/app.js）

1. **bindEvents 新建文件按钮**：改为判空 + 兼容新 id
   ```js
   const newFileBtn = document.getElementById('new-file-btn') || document.getElementById('quick-new-file');
   if (newFileBtn) newFileBtn.addEventListener('click', ...);
   ```

2. **init() 容错**：phase 1 出错时只记录错误横幅，**不再 return**，保证 setupMonaco / setupTerminal 必定执行
   ```js
   } catch(e) {
     console.error('Init phase 1 error:', e);
     document.body.insertAdjacentHTML('beforeend', `<div ...>INIT ERROR: ${e.message}</div>`);
     // 不再 return
   }
   ```

3. **setupMonaco 重写为自愈模式**：
   - 新增 `ensureMonacoEditor()`（幂等：已就绪直接返回；否则创建编辑器、注册事件、按 data-theme 选 vs/labcode-dark、补渲染已打开文件）
   - 加载采用双保险：AMD 回调（正常路径）+ **1 秒轮询最多 90 次**（覆盖回调丢失 / asar 首次慢加载 / 模块缓存异常）
   - 浅色主题固定 `vs`（白底），深色才用 `labcode-dark`（修复原代码固定黑底的问题）

4. **openFile / write_file 重试逻辑**：每次重试前先调 `ensureMonacoEditor()` 确保编辑器就绪，消除竞态。

## 五、经验教训

1. **init() 中任何初始化失败都不应阻断后续模块初始化**——用 try/catch 分块隔离，单模块失败只影响自身。
2. 页面元素 id 重命名时，必须全局搜索 JS 中的引用（`new-file-btn` 只改了 HTML 忘了 JS）。
3. Monaco 类重型库的初始化必须多层兜底：正常回调 + 轮询 + 幂等 create，才能覆盖 asar 慢加载等 Electron 特有场景。
4. 本环境 Electron 窗口不可见，只能靠 CDP Runtime.evaluate + 控制台捕获验证——**先抓 console 错误再猜代码**，效率高得多。
