# 编译功能修复与实测记录

> 日期：2026-09-10

> 工程：`D:\工作\LabCode\desktop-app`

## 一、问题背景

用户反馈"点编译没有编译过程/无反应"。经实测排查，编译按钮链路本身存在，但有两个缺陷导致体验异常：

### 缺陷 1：Arduino sketch 目录结构不匹配（根因）

`arduino-cli` 严格要求主 `.ino` 文件名必须与所在目录同名（如 `esp32_robot/esp32_robot.ino`）。

用户的 PlatformIO 风格项目结构为：

```
esp32-robot/
├── platformio.ini
├── src/
│   ├── esp32_robot.ino   ← 主程序
│   ├── Robot.cpp
│   └── Robot.h
```

点击编译后 arduino-cli 报错：

```
Can't open sketch: main file missing from sketch: ...\src\src.ino
```

**修复**：`main/index.js` 新增 `normalizeSketchDir()`——当 `.ino` 所在目录名与文件名不一致时，自动创建临时同名目录（`os.tmpdir()/labcode-sketch-xxx/esp32_robot/`），复制 sketch 源文件后编译，编译完成自动清理临时目录。`compile:arduino` 与 `compile:upload` 均接入该逻辑。

### 缺陷 2：核心插件默认未安装

编译按钮依赖插件市场安装的 "Arduino 编译上传" 插件（`installedPlugins` 含 `compile` 能力）。新用户首次启动时 localStorage 为空 → 点击编译只弹"请先在插件市场安装 Arduino 编译插件"提示，用户感知为"没反应"。

**修复**：`app.js` 首次启动自动安装核心插件 `arduino / serial-monitor / plotter`（标记 `labcode_core_plugins_initialized`），对标 TrieCode 编译/串口功能开箱即用；大模型运行时与模型插件仍由用户在插件市场自行安装。
