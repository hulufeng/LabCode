## 二、AI 端到端 UI 测试发现的 4 个缺陷与修复

### 缺陷 1：AI 气泡最终为空 / 只显示最后一个字符（核心）

**现象**：模型流式输出正常（CDP 直测 `chatStream` 完整 delta），但 UI 气泡空或只剩"。"

**根因**：`run()` 中 `onStreamDelta = (delta) => this._stream(delta, false)` —— **delta 是增量**，但 `handleAISend` 的 `onStream` 回调把 content 当**累积全文**覆盖赋值 `currentAIBubble.textContent = content`。每次 delta 覆盖，最终只剩最后一段。

**修复**（`renderer/js/app.js` ~2846）：
```js
this._streamAcc = '';
this.ai.onStreamDelta = (delta) => {
  this._streamAcc += delta;   // 增量累积为全文
  this._stream(this._streamAcc, false);  // 上屏累积全文
};
```

### 缺陷 2：工具调用轮后无总结（工具执行了但界面空）

**现象**：模型输出工具 JSON → 工具执行 → 界面无 AI 总结，只剩一个空气泡。

**根因**：`run()` 工具轮结束后执行 `this._stream('', true); return;` —— 工具结果**没有反馈给模型**就结束循环，且 `_stream('', true)` 创建空气泡。

**修复**（~3157）：改为 `continue;`，让工具结果进入下一轮，模型基于结果生成最终总结。

### 缺陷 3：本地模型输出 ```json 代码块包裹的工具 JSON 无法识别

**现象**：qwen2.5-coder 等本地模型常输出：
```
```json
{"name": "read_file", "arguments": {...}}
```
```
原抑制逻辑只匹配 `{`/`[` 开头 → 不抑制 → 工具 JSON 直接当文本显示，且 `_parseToolCalls` 解析失败 → 工具不执行。

**修复**：
- 抑制正则增强：`/^[\{\[]/` 或 `/^```(?:json)?\s*[\{\[]/`
- `_parseToolCalls` 增强：剥离 ```json 代码块再解析；兼容 `{"tool_calls": [...]}` 包装；保留代码块外文本

### 缺陷 4：抑制触发前已上屏的代码块前缀与补上屏内容重复（双 ```json）

**现象**：误判抑制后，done 补上屏完整原文，与抑制前已上屏的 ` ```json ` 前缀叠加成双份。

**修复**：done 补上屏前先调 `onStreamDeltaReset` 重置累积缓冲，再上屏完整原文。
